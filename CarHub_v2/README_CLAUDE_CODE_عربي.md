# 🤖 برومبت Claude Code — تحويل شاشات CarHub إلى Flutter (المرحلة 0 + 1)

> **لوائل (مسؤول Flutter + UI/UX).**
> افتح مجلد المشروع في VS Code مع Claude Code، والصق البرومبت التالي.
> المدخلات: `client_app/` و`business_app/` (ملفات HTML + صور PNG) و`_design/DESIGN.md`.

---

## البرومبت (انسخه إلى Claude Code)

```
مهم: تحدّث معي بالعربية دائماً. اشرح كل قراراتك وخطواتك بالعربية، وأبقِ 
أسماء المتغيّرات والكود بالإنجليزية كالمعتاد.

أنت تساعدني في بناء تطبيق "CarHub" بلغة Flutter، عبر تحويل شاشات مصمّمة مسبقاً 
(HTML من Stitch) إلى Flutter. خبرتي متوسطة في Flutter. اشرح قراراتك قبل كتابة 
الكود، وسِر خطوة بخطوة، وبعد كل خطوة أخبرني كيف أختبرها.

## المدخلات
- مجلّدا `client_app/` و`business_app/` فيهما شاشات HTML (Tailwind CSS، عربية 
  RTL، خط Readex Pro، أيقونات Material Symbols) + صورة PNG لكل شاشة.
- `_design/DESIGN.md` فيه ألوان التصميم ونظام الخطوط بدقة.
- ملفات HTML هي "مصدر الحقيقة" لشكل كل شاشة: طابِق التخطيط والألوان والمسافات 
  ونصف القطر (radius) والخطوط بأمانة في Flutter.

## النطاق — نفّذ الآن المرحلة 0 + 1 فقط
ابنِ الأساس + ميزة الحسابات والملف الشخصي فقط. لا تبنِ السوق أو المناقصات أو 
الشات أو منطق الذكاء الاصطناعي الآن — لكن جهّز التنقّل والمكوّنات المشتركة 
بحيث تُضاف لاحقاً بسهولة.

### المرحلة 0 — الأساس
1. أنشئ مشروع Flutter ببنية feature-first نظيفة:
   lib/
     core/     (config, theme, network, storage, routing, utils)
     shared/   (widgets مشتركة: أزرار، حقول، تحميل، زر الذكاء الاصطناعي)
     features/
       auth/     (data / logic / presentation)
       profile/  (data / logic / presentation)
2. حوّل `_design/DESIGN.md` إلى Theme في Flutter: AppTheme مركزي فيه 
   ColorScheme (الأساسي أخضر #00B761، الكحلي #0A192F، الأسطح، الخطأ)، ونظام 
   خطوط Readex Pro، وثوابت المسافات، وبطاقة افتراضية بنصف قطر 16px وظل ناعم.
3. دعم RTL كامل وتعريب (Directionality.rtl، locale ar).
4. إدارة الحالة: استخدم Riverpod. اشرح الاختيار بإيجاز، وجهّزه.
5. التنقّل: go_router مع حماية مسارات (غير المسجّل يصل فقط لـ 
   splash/login/register/otp).
6. طبقة الشبكة: Dio مع base URL و interceptor للتوكن ومعالجة الأخطاء. مهم: 
   الـ Backend (Laravel) غير جاهز بعد، لذا ابنِ طبقة Mock repository خلف 
   interface، لأتمكّن من تشغيل التطبيق والتنقّل ببيانات وهمية الآن، واستبدالها 
   بالـ API الحقيقي لاحقاً دون تغيير الواجهات.
7. تخزين آمن للتوكن عبر flutter_secure_storage.

### المرحلة 1 — الحسابات والملف الشخصي (ابنِ هذه الشاشات)
حوّل شاشات HTML التالية إلى شاشات Flutter مطابِقة للـ HTML:
- client_app/01_splash.html          → SplashScreen
- client_app/02_login.html           → LoginScreen
- client_app/03_register.html        → RegisterScreen
- client_app/04_otp_verification.html → OtpScreen
- client_app/24_profile.html         → ProfileScreen
وأضف EditProfileScreen (غير موجودة في HTML — صمّمها متسقة مع شاشة الملف: رفع 
صورة عبر image_picker، حقول الاسم/الهاتف/المدينة، زر حفظ أخضر).

منطق المصادقة (بـ Mock الآن):
- تسجيل → OTP → دخول.
- تسجيل دخول → دخول؛ بيانات خاطئة تُظهر خطأ.
- حفظ التوكن؛ دخول تلقائي عند إعادة فتح التطبيق؛ تسجيل خروج يمسح التوكن.

## متطلب خاص — زر الذكاء الاصطناعي العائم (مهم جداً)
أنشئ widget واحداً مشتركاً اسمه `FloatingAiButton` و`ClientScaffold` (غلاف حول 
Scaffold) يُظهر هذا الزر العائم في كل شاشات تطبيق العميل — زر دائري أخضر بأيقونة 
روبوت، ظل ناعم، مثبّت أسفل اليسار (RTL)، عائم فوق المحتوى وفوق شريط التنقّل، مع 
نبض خفيف. الضغط عليه يفتح شاشة المساعد الذكي كـ overlay.
ابنِه مرة واحدة كمكوّن مشترك؛ كل شاشات العميل تعيد استخدامه (لا تنسخه في كل 
شاشة). الآن يكفي أن يفتح شاشة مساعد مبدئية — منطق الـ AI يأتي لاحقاً، لكن الزر 
يجب أن يكون حاضراً في كل الشاشات من البداية.
ملاحظة: شاشات HTML الحديثة (مثل my_orders، marketplace، product_details) تُظهر 
هذا الزر أصلاً — اعتمدها مرجعاً لموضعه وشكله.

## مكوّنات مشتركة تُبنى مرة وتُعاد (استخرجها من HTML)
PrimaryButton (أخضر pill)، SecondaryButton (ghost/outline)، AppTextField (حقل 
بظل ناعم)، StatusPill، ProductCard مبدئي، شريط التنقّل السفلي العائم، 
وFloatingAiButton أعلاه.

## قواعد العمل
- تحدّث بالعربية دائماً، واشرح كل قرار قبل الكود.
- سلّم الكود تدريجياً: هيكل المشروع أولاً، ثم Theme، ثم Network+Mock، ثم 
  Routing، ثم شاشات المصادقة، ثم الملف الشخصي.
- بعد كل خطوة أخبرني كيف أشغّلها وأختبرها قبل الانتقال.
- كل شيء RTL وعربي، ومطابق لـ HTML بصرياً.
- لا تبنِ ميزات خارج المرحلة 0 + 1، لكن اترك نقاط توسّع نظيفة 
  (routes، مجلدات، widgets) للسوق والمناقصات والشات والـ AI لاحقاً.
- أخبرني بما يجب تنسيقه مع مبرمجة الـ Backend (إسراء): مسارات وأشكال استجابة 
  الـ API للمصادقة والملف الشخصي.

## عقود الـ API (أشكال مبدئية للـ Mock، تطابق الـ Backend المستقبلي)
- POST /register   → { token, user }
- POST /login      → { token, user }
- POST /verify-otp
- POST /forgot-password
- GET  /me         → { user }   (للدخول التلقائي)
- GET  /profile    → { profile }
- PUT  /profile
- POST /profile/avatar

ابدأ بالمرحلة 0 خطوة 1 (هيكل المشروع)، واشرح المعمارية بالعربية قبل توليد الكود.
```
